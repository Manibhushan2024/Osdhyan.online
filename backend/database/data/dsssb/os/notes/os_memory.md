# Memory Management & Virtual Memory

**In 30 seconds**
- **Logical (virtual) address** = generated by the CPU; **physical address** = seen by the memory unit. The **MMU** maps logical to physical at run time.
- **Paging** removes external fragmentation (frames = fixed-size physical blocks, pages = same-size logical blocks); logical address = **page number (p) + offset (d)**. Segmentation gives external fragmentation; paging gives internal fragmentation (last page).
- TLB: EAT = h(t + m) + (1 − h)(t + 2m). Example: 80% hits, m = 100 ns, t ≈ 0 → **120 ns**.
- ⭐ Asked in DSSSB: **virtual memory** gives an **illusion of an extremely large main memory**; implemented by **demand paging** (a **lazy swapper** — never brings a page in until it is needed).
- ⭐ Asked in DSSSB: a **page fault** is a reference to a page **not currently in main memory** (page marked invalid) → trap to the OS.
- Page replacement: **OPT** = fewest faults (needs future); **LRU** = good approximation; **FIFO** = simplest.
- ⭐ Asked in DSSSB: **Belady's anomaly** — more frames, more faults — occurs in **FIFO** (1,2,3,4,1,2,5,1,2,3,4,5: **9** faults with 3 frames, **10** with 4). **LRU and OPT are stack algorithms and never suffer from it**.
- **Thrashing**: a process spends more time paging than executing; controlled by the **working-set model** or **page-fault frequency**.

## 1. Basics: address binding

A program on disk becomes a process through several steps (compile → link → load). Binding of instructions and data to memory addresses can happen at:

| Binding time | When possible | Result |
|---|---|---|
| **Compile time** | Process location in memory is known in advance | **Absolute code**; if the start location changes, the code must be **recompiled** (e.g. MS-DOS .COM programs) |
| **Load time** | Location not known at compile time | Compiler generates **relocatable code**; final binding delayed until load; if start address changes, just **reload** |
| **Execution (run) time** | Process can be **moved during execution** | Needs special hardware (MMU); **used by most general-purpose operating systems** |

### Logical vs physical address
| Logical (virtual) address | Physical address |
|---|---|
| Generated by the **CPU** | Address seen by the **memory unit** (loaded into the memory-address register) |
| Set of all = logical address space | Set of all = physical address space |
| User program deals only with logical addresses; it never sees real physical addresses | Real location in RAM |

- Compile-time and load-time binding: **logical = physical**. Execution-time binding: they **differ** (the logical address is then called a **virtual address**).
- **Memory-Management Unit (MMU):** hardware device that maps virtual to physical addresses at run time. Simplest scheme: a **relocation register** (base) is added to every address. Relocation = 14000, logical 346 → physical **14346**.

### Base and limit registers (protection)
- **Base register** = smallest legal physical address; **limit register** = size of the range.
- Example: base 300040, limit 120900 → legal addresses **300040 to 420939** (base + limit − 1).
- Every user-mode address is compared: if address ≥ base + limit (or < base) → **trap** (addressing error). Only the OS (kernel mode, privileged instructions) can load these registers.

### Dynamic loading and dynamic linking
- **Dynamic loading:** a routine is **not loaded until it is called**; all routines stay on disk in relocatable form. Better memory-space utilisation; unused routines (e.g. error handlers) are never loaded. **Needs no special OS support** (the program's design handles it).
- **Dynamic linking:** **linking** is postponed until execution time — used for system libraries (**shared libraries / DLLs**). A small **stub** in the image locates the routine. Saves disk and memory; library updates need no relinking. **Needs OS help** (to check whether the routine is in another process's memory). **Static linking** copies libraries into every binary image.

## 2. Swapping

A process can be **swapped** temporarily out of memory to a **backing store** (fast disk) and brought back for continued execution — this lets the total address space of all processes exceed real physical memory.
- **Roll out, roll in:** a priority-based variant — lower-priority process swapped out so a higher-priority one can run.
- Major cost is **transfer time**, proportional to the amount swapped. Example: 100 MB process, transfer rate 50 MB/s → 2 s out + 2 s in = **4 s** total swap time.
- Never swap a process with **pending I/O** into its memory buffers (or use OS buffers — double buffering).
- Standard swapping is rarely used now; modern systems swap **pages** (paging), and mobile systems (iOS, Android) generally **do not support swapping**.

## 3. Contiguous memory allocation

Memory has two partitions: the **OS** (usually low memory, with the interrupt vector) and **user processes**. Each process is in a single contiguous section. Protection by relocation + limit registers.

| Fixed (static) partitions (MFT) | Variable (dynamic) partitions (MVT) |
|---|---|
| Memory divided into fixed-size partitions; one process per partition | OS keeps a table of free blocks (**holes**); a process gets exactly what it needs |
| Degree of multiprogramming bounded by number of partitions | Holes of various sizes are scattered in memory |
| Suffers **internal** fragmentation | Suffers **external** fragmentation |

### Dynamic storage-allocation strategies
| Strategy | Rule | Notes |
|---|---|---|
| **First fit** | Allocate the **first** hole big enough | Fastest (stop searching early) |
| **Best fit** | Allocate the **smallest** hole big enough | Must search whole list (unless sorted); leaves smallest leftover hole |
| **Worst fit** | Allocate the **largest** hole | Leaves largest leftover hole; must search whole list |
| **Next fit** | Like first fit, but search starts from where the **last** search ended | Variant of first fit |

Simulations: **first fit and best fit are better than worst fit** in time and storage utilisation; first fit is generally faster.

#### Worked example (Silberschatz exercise; verified)
Partitions in order: **100, 500, 200, 300, 600 KB**. Processes in order: **212, 417, 112, 426 KB**.

| Process | First fit | Best fit | Worst fit | Next fit |
|---|---|---|---|---|
| 212 | 500 (288 left) | 300 (88 left) | 600 (388 left) | 500 (288 left) |
| 417 | 600 (183 left) | 500 (83 left) | 500 (83 left) | 600 (183 left) |
| 112 | 288 hole of the 500 (176 left) | 200 (88 left) | 388 hole of the 600 (276 left) | 183 hole of the 600 (71 left) |
| 426 | **must wait** | 600 (174 left) | **must wait** | **must wait** |

Only **best fit** places all four processes here. (Next fit: the search for 112 starts at the 600 partition, where 417 was placed.)

### Fragmentation
| Internal fragmentation | External fragmentation |
|---|---|
| Unused memory **inside** an allocated partition/block | Enough total free memory exists, but it is **not contiguous** (scattered small holes) |
| Fixed partitions, **paging** (last page) | Variable partitions, **segmentation** |
| Cure: smaller blocks/pages | Cures: **compaction**, or non-contiguous allocation (**paging**, segmentation) |

- **50-percent rule:** with first fit, given N allocated blocks, another 0.5N blocks are lost to fragmentation — **one-third of memory may be unusable**.
- **Compaction:** shuffle memory contents to place all free memory together in one large block. Possible **only if relocation is dynamic** (execution-time binding); can be expensive.

## 4. Paging

Paging lets the physical address space of a process be **non-contiguous**; it **avoids external fragmentation** and the need for compaction.
- Physical memory is broken into fixed-size blocks called **frames**; logical memory into blocks of the same size called **pages**.
- Page size is a **power of 2** (typically 4 KB to 8 KB; range from 512 bytes up to 1 GB on some machines).
- The **page table** (one per process) holds the base address (frame number) of each page. The OS keeps a **frame table** (one entry per physical frame: free or allocated, to which page of which process).
- **Page-table base register (PTBR)** points to the page table; **page-table length register (PTLR)** gives its size.

### Address split
If logical address space = 2^m and page size = 2^n bytes:

| page number p | page offset d |
|---|---|
| m − n bits (index into page table) | n bits |

Physical address = (frame number × page size) + d.

### Paging numericals (all verified)
**(a) Tiny Silberschatz example.** Page size 4 bytes, page table: page 0 → frame 5, 1 → 6, 2 → 1, 3 → 2.

| Logical | p, d | Frame | Physical = f × 4 + d |
|---|---|---|---|
| 0 | 0, 0 | 5 | **20** |
| 3 | 0, 3 | 5 | **23** |
| 4 | 1, 0 | 6 | **24** |
| 13 | 3, 1 | 2 | **9** |

**(b)** Page size 1 KB, logical address 3085, page 3 is in frame 7.
1. p = 3085 div 1024 = **3**; d = 3085 mod 1024 = **13**.
2. Physical = 7 × 1024 + 13 = **7181**.

**(c)** 16-bit logical address 0x3A7F, page size 2 KB (2^11) → offset 11 bits, page 5 bits. 0x3A7F = 14975 → page = 14975 div 2048 = **7**, offset = **639**.

**(d) Bits.** Logical space of 64 pages of 1024 words each; physical memory of 32 frames.
- Logical address = 64 × 1024 = 2^16 → **16 bits** (6 page + 10 offset).
- Physical address = 32 × 1024 = 2^15 → **15 bits** (5 frame + 10 offset).

**(e) Page-table size.** 32-bit logical address, 4 KB pages, 4-byte page-table entry (PTE).
1. Offset = 12 bits; page number = 32 − 12 = 20 bits.
2. Number of pages = 2^20 = **1,048,576** (1 M).
3. Page-table size = 2^20 × 4 B = **4 MB** per process.
- Physical memory 256 MB with 4 KB frames → 2^28 / 2^12 = **65,536 frames** (16-bit frame number).

**(f) Internal fragmentation.** Page size 2,048 B, process 72,766 B → 35 full pages + 1,086 B → needs **36 frames**; internal fragmentation = 2,048 − 1,086 = **962 bytes**. Worst case: a whole frame minus 1 byte; on average **half a page** per process.

### Protection and sharing
- A **valid–invalid bit** in each PTE: *valid* = page is in the process's logical address space; *invalid* = illegal page (trap). Protection bits mark pages read-only / read-write / execute-only.
- **Shared pages:** **reentrant (pure) code** — non-self-modifying, never changes during execution — can be shared. Example: 40 users run a 150 KB editor with 50 KB private data each: without sharing 40 × 200 = **8,000 KB**; with sharing 150 + 40 × 50 = **2,150 KB**.

## 5. Translation look-aside buffer (TLB)

With the page table in memory, each data access needs **two** memory accesses (one for the PTE, one for the data). Fix: a **TLB** — a small, fast **associative memory** (each entry = key (page no.) + value (frame no.)), searched in parallel; typically 32 to 1,024 entries.
- **TLB hit:** frame number obtained immediately. **TLB miss:** page table referenced in memory, then the entry is added to the TLB (replacing one if full; some entries can be **wired down**).
- **ASIDs** (address-space identifiers) let the TLB hold entries of several processes; otherwise the TLB is **flushed** on each context switch.
- **Hit ratio** = percentage of times the page number is found in the TLB. **TLB reach** = entries × page size (64 entries × 4 KB = 256 KB).

**Effective access time:** EAT = h × (t + m) + (1 − h) × (t + 2m), where h = hit ratio, t = TLB search time, m = memory access time.

| h | t | m | EAT |
|---|---|---|---|
| 0.80 | 0 (negligible) | 100 ns | 0.8 × 100 + 0.2 × 200 = **120 ns** (20% slowdown) |
| 0.99 | 0 | 100 ns | 0.99 × 100 + 0.01 × 200 = **101 ns** |
| 0.80 | 20 ns | 100 ns | 0.8 × 120 + 0.2 × 220 = **140 ns** |
| 0.98 | 20 ns | 100 ns | 0.98 × 120 + 0.02 × 220 = **122 ns** |
| 0.90 | 10 ns | 100 ns | 0.9 × 110 + 0.1 × 210 = **120 ns** |

With a **two-level** page table a miss costs t + 3m: h = 0.98, t = 20, m = 100 → 0.98 × 120 + 0.02 × 320 = **124 ns**.

## 6. Structure of the page table

| Type | Idea | Key facts |
|---|---|---|
| **Hierarchical (multilevel)** | Page the page table itself | 32-bit address, 4 KB page: **p1 = 10, p2 = 10, d = 12** (two-level, "forward-mapped"); each level = 1,024 entries. Impractical for 64-bit (too many levels) |
| **Hashed page table** | Virtual page number is **hashed** into a table; each entry is a linked list of (VPN, frame, next pointer) | Common for address spaces **larger than 32 bits**; variant: **clustered** page tables (each entry covers several pages) |
| **Inverted page table** | **One entry per physical frame** (real page), holding <process-id, page-number> | One table for the whole system; **decreases memory** for page tables but **increases search time** (use a hash table); makes **shared memory hard**. Used in 64-bit UltraSPARC and PowerPC |

## 7. Segmentation

Segmentation supports the **user's view of memory**: a program is a collection of segments (main program, functions, stack, symbol table, arrays…), each of variable length.
- Logical address = **<segment-number, offset>**.
- **Segment table:** each entry has a **base** (starting physical address) and a **limit** (length). **STBR** points to the table; **STLR** gives the number of segments.
- Translation: if offset d < limit → physical = base + d; else **trap** (addressing error beyond end of segment).
- No internal fragmentation, but **external fragmentation** (segments vary in size).

### Worked translation (Silberschatz; verified)
| Segment | Base | Limit |
|---|---|---|
| 0 | 1400 | 1000 |
| 1 | 6300 | 400 |
| 2 | 4300 | 400 |
| 3 | 3200 | 1100 |
| 4 | 4700 | 1000 |

| Logical <s, d> | Check d < limit | Physical |
|---|---|---|
| <2, 53> | 53 < 400 ✓ | 4300 + 53 = **4353** |
| <3, 852> | 852 < 1100 ✓ | 3200 + 852 = **4052** |
| <1, 399> | 399 < 400 ✓ | **6699** |
| <0, 1222> | 1222 ≥ 1000 ✗ | **trap** |
| <4, 1000> | 1000 ≥ 1000 ✗ | **trap** (offsets run 0 to limit − 1) |

### Paging vs segmentation
| Paging | Segmentation |
|---|---|
| Fixed-size pages; invisible to the programmer | Variable-size, logical units; visible to the programmer |
| Internal fragmentation | External fragmentation |
| Page table: frame numbers | Segment table: base + limit |
| Address: <p, d> | Address: <s, d> |

### Segmentation with paging
Segments are themselves paged, combining the user view with no external fragmentation. **Intel IA-32 (Pentium):** CPU generates a logical address → **segmentation unit** → **linear address** → **paging unit** → physical address. A segment can be up to 4 GB; up to 16 K segments per process (8 K in the **LDT**, private; 8 K in the **GDT**, shared); a 16-bit **selector** = 13-bit segment number, 1 bit for GDT/LDT, 2 bits protection. Linux on IA-32 uses only six segments and relies mostly on paging.

## 8. Virtual memory ⭐ Asked in DSSSB

**Virtual memory** is a technique that allows the execution of processes that are **not completely in memory**. It separates user logical memory from physical memory, so programmers see an **extremely large virtual memory** while only a smaller physical memory is available — it is **an illusion of an extremely large main memory** (DSSSB 2023 answer).

Benefits:
- Programs are no longer constrained by the amount of physical memory.
- More programs can run at the same time → higher CPU utilisation and throughput.
- Less I/O is needed to load or swap programs → each program runs faster to start.
- Easy sharing of files and memory (shared libraries, shared memory), efficient process creation (**copy-on-write** with fork()).

**Virtual address space** = the logical view of how a process is stored: code and data at low addresses, heap growing up, stack growing down, with a large **hole** between them (a **sparse** address space).

Implemented by **demand paging** (also demand segmentation).

## 9. Demand paging

Load pages **only as they are needed**; pages never accessed are never loaded.
- A demand-paging system is like paging with swapping, but uses a **lazy swapper**: it **never swaps a page into memory unless that page will be needed**. A swapper that works on pages is called a **pager**.
- **Valid–invalid bit:** valid = page is legal and in memory; invalid = page is either not in the logical address space or is valid but currently on disk.
- **Pure demand paging:** start the process with **no** pages in memory; never bring a page in until it is required.
- Works well because of **locality of reference**.
- Hardware needed: page table with valid–invalid bit, **secondary memory (swap space)**, and the ability to **restart any instruction** after a page fault.

### Page fault ⭐ Asked in DSSSB
A **page fault** is an access to a page **not currently in memory** (marked invalid). The paging hardware notices the invalid bit and **traps** to the OS. (It is a normal event, not an error that always occurs.)

**Steps to service a page fault (Silberschatz):**
1. Check an internal table (usually kept with the PCB) to decide whether the reference was a **valid or invalid** memory access.
2. If **invalid**, **terminate** the process. If valid but the page is not yet in memory, page it in.
3. Find a **free frame** (from the free-frame list).
4. Schedule a **disk operation** to read the desired page into the new frame.
5. When the disk read is complete, **update the internal table and the page table** to show the page is now in memory.
6. **Restart the instruction** that was interrupted by the trap.

### Effective access time with page faults
EAT = (1 − p) × ma + p × page-fault service time, where p = page-fault rate (0 ≤ p ≤ 1).

**Numerical (Silberschatz; verified):** ma = 200 ns, page-fault service time = 8 ms = 8,000,000 ns.
1. EAT = (1 − p) × 200 + p × 8,000,000 = **200 + 7,999,800 × p** ns.
2. If p = 1/1000: EAT = 200 + 7,999.8 = **8,199.8 ns ≈ 8.2 µs** — slowed by a factor of about **40**.
3. For less than 10% slowdown (EAT < 220): 20 > 7,999,800 × p → **p < 0.0000025**, i.e. fewer than **1 fault in 399,990** accesses.

**With dirty pages:** ma = 100 ns; service = 8 ms if the victim is clean, 20 ms if it is modified; 70% of victims are modified. Average service = 0.3 × 8 + 0.7 × 20 = **16.4 ms**. For EAT ≤ 200 ns: 200 = 100 + p(16,400,000 − 100) → **p ≈ 6.1 × 10⁻⁶**.

## 10. Page replacement

If no frame is free, a page must be replaced (otherwise we would over-allocate memory).

**Basic page replacement:**
1. Find the desired page on disk.
2. Find a free frame; if none, use a **page-replacement algorithm** to select a **victim** frame; write the victim to disk (if modified) and update tables.
3. Read the desired page into the freed frame; update tables.
4. Restart the process.

- Without a free frame, **two page transfers** (out + in) are needed. The **modify (dirty) bit** avoids writing back pages that were not changed.
- Algorithms are compared by running them on a **reference string** and counting page faults. More frames → generally fewer faults.

### The algorithms
| Algorithm | Victim | Notes |
|---|---|---|
| **FIFO** | Oldest page in memory | Simple (a queue); suffers **Belady's anomaly** |
| **Optimal (OPT / MIN)** | Page that **will not be used for the longest period of time** | **Lowest fault rate** of all; never suffers Belady; needs **future knowledge** → used only for **comparison** |
| **LRU** | Page **not used for the longest period** (OPT looking backward) | Good approximation of OPT; needs hardware: **counters** (time-of-use) or a **stack** of page numbers; stack algorithm |
| **LRU approximations** | Use the **reference bit** set by hardware | Additional-reference-bits (8-bit shift register), **second-chance (clock)**, enhanced second-chance (reference, modify) pair: (0,0) best victim → (1,1) worst |
| **LFU** | Page with **smallest** reference count | Heavily used early page may stay forever (fix: shift counts right periodically) |
| **MFU** | Page with **largest** count | Argument: smallest count = probably just brought in |

**Second-chance (clock):** pages in a circular queue with a pointer. On a fault, inspect the page at the pointer: if its reference bit = 0, replace it; if 1, clear the bit (give a **second chance**), and advance. If all bits are 1 it degenerates to **FIFO**.

## 11. Belady's anomaly ⭐ Asked in DSSSB

**Belady's anomaly:** for some page-replacement algorithms, the page-fault rate may **increase** as the number of allocated frames **increases**.
- **FIFO** shows it: string 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 → **9 faults with 3 frames, 10 faults with 4 frames**.
- FIFO fault counts for 1 to 7 frames on this string: 12, 12, **9, 10**, 5, 5, 5.
- **Stack algorithms** never show it: the set of pages in memory with n frames is always a **subset** of the set with n + 1 frames. **LRU and OPT are stack algorithms.**
- DSSSB 2024: "Which does not suffer from Belady's anomaly — I. LRU, II. FIFO?" → **Only I (LRU)**.
- Second-chance (clock) is FIFO-based and can also show the anomaly; MFU can too.

## 12. Allocation of frames

- **Minimum** frames per process is defined by the **computer architecture** (the instruction set: an instruction and its operands that may span pages must all be in memory). **Maximum** is defined by the available physical memory.

| Equal allocation | Proportional allocation |
|---|---|
| m frames, n processes → m/n each | aᵢ = (sᵢ / S) × m, where sᵢ = size of process i, S = Σsᵢ |
| 93 frames, 5 processes → **18** each, 3 left in the free-frame pool | 62 frames, processes of 10 and 127 pages → 10/137 × 62 ≈ **4**, 127/137 × 62 ≈ **57** |

**Priority allocation:** proportional by priority (or size + priority).

| Global replacement | Local replacement |
|---|---|
| A process selects a replacement frame from the set of **all** frames, even one held by another process | Each process selects only from **its own** allocated frames |
| A process cannot control its own fault rate | Number of frames per process stays fixed |
| **Greater system throughput**; more commonly used | May hinder a process by not making free frames available |

**NUMA:** on non-uniform memory access systems, allocate frames "as close as possible" to the CPU running the process.

## 13. Thrashing

A process is **thrashing** if it is spending **more time paging than executing**.

**Cause (Silberschatz):**
1. CPU utilisation is low, so the OS **increases the degree of multiprogramming**.
2. A new process (with global replacement) takes frames from others; they fault, queue for the paging device; the ready queue empties.
3. CPU utilisation drops further → OS adds more processes → more faults. Throughput plunges; effective memory access time rises.

The plot of CPU utilisation vs degree of multiprogramming rises, peaks, then falls sharply — that fall is thrashing.

**Remedies:**
- **Local (priority) replacement** limits thrashing to one process (does not fully solve it).
- Provide each process as many frames as it needs — based on the **locality model** (a process moves from locality to locality; a locality is a set of pages actively used together).
- **Working-set model:** Δ = working-set window (a fixed number of most recent page references). The **working set** = set of pages in the most recent Δ references. **D = ΣWSSᵢ** = total demand for frames. If **D > m** (available frames) → thrashing will occur → **suspend** a process (its pages are swapped out). Keeps multiprogramming as high as possible while preventing thrashing. Approximated with a timer interrupt + reference bits.
  - Example (Δ = 4; verified): reference string 1, 2, 3, 2, 1, 4, 4, 4, 5, 4, 4, 3. After the 5th reference the window is 2, 3, 2, 1 → WS = {1, 2, 3}, WSS = 3. After the 8th: 1, 4, 4, 4 → WS = {1, 4}, WSS = 2. After the 12th: 5, 4, 4, 3 → WS = {3, 4, 5}, WSS = 3.
  - Δ too small → misses the locality; Δ too large → overlaps several localities; Δ = ∞ → whole program.
- **Page-fault frequency (PFF):** set an **upper and a lower bound** on the desired fault rate. Rate above the upper bound → give the process **another frame**; below the lower bound → **remove a frame**. If no free frame is available, suspend a process.

## 14. Other considerations (one line each)

- **Copy-on-write:** after fork(), parent and child share pages; a page is copied only when either process writes to it.
- **Prepaging:** bring in at once some or all pages that will be needed, to cut the initial burst of faults.
- **Page size:** larger pages → smaller page table, fewer faults, more internal fragmentation; smaller pages → better locality resolution, less internal fragmentation.
- **Kernel memory:** allocated from a separate free-memory pool, using the **buddy system** (power-of-2 sizes; adjacent buddies coalesce) and **slab allocation** (caches of objects; no fragmentation from slabs).
- **I/O interlock:** a lock bit keeps pages used for I/O from being replaced.

## 15. Memory-mapped files

**Memory mapping** a file allows a part of the virtual address space to be logically associated with the file: a disk block is mapped to a page (or pages) in memory.
- Initial access proceeds through ordinary **demand paging** (a page fault reads a page-sized portion of the file into a physical page).
- Afterwards, reads and writes to the file are handled as **routine memory accesses** — no read()/write() system calls, so file I/O becomes faster and simpler.
- Writes to the mapped memory need not reach disk immediately; they are written when the file is closed or periodically.
- **Several processes may map the same file** concurrently to share data (this is also how shared memory is done in Windows). Unix/Linux system call: **mmap()**.

## 16. Cache vs main memory

**Cache** is a small, very fast memory (SRAM) between the CPU and main memory that holds copies of recently used words; it is managed by **hardware** and exploits **locality of reference** — a hit avoids a slower main-memory access. **Main memory (RAM, DRAM)** is larger, slower and cheaper per byte, is the only large storage the CPU can access directly, and is managed by the **operating system** (paging, allocation). The TLB is a special cache of page-table entries. Virtual memory plays the same game one level down: main memory acts as a "cache" for the disk, with page faults as the misses — but it is *virtual memory*, not cache memory, that gives the illusion of a very large main memory.

## Exam traps
1. **Virtual memory**, not cache or associative memory, is "the illusion of an extremely large main memory".
2. A page fault means the page is **not in memory** — fetching the page is the OS's *response*, not the fault itself.
3. Belady's anomaly belongs to **FIFO**; LRU and OPT (stack algorithms) never show it. "More frames always mean fewer faults" is **false** for FIFO.
4. OPT replaces the page used **farthest in the future**; LRU replaces the page used **farthest in the past**. Do not swap them.
5. Count the **initial** loads as page faults unless the question says otherwise.
6. Paging → **internal** fragmentation (no external); segmentation and variable partitions → **external**.
7. Compaction is possible only with **execution-time** (dynamic) relocation.
8. Page-number bits = logical bits − offset bits; offset bits = log₂(page size). Page-table entries = number of **pages**; inverted table entries = number of **frames**.
9. Without a TLB, each access costs **2m**; a TLB miss costs **t + 2m**, not t + m.
10. Segment offset must be **less than** the limit; offset = limit is a trap.
11. Dynamic loading needs **no** OS support; dynamic linking **does**.
12. Thrashing is cured by **reducing** the degree of multiprogramming (suspend processes), not by adding more processes.
